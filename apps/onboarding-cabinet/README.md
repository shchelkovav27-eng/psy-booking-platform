# Сопровождение в профессию — кабинет менеджеров онбординга

Третья система рядом со школой (`/shkola`, таблицы `shk_*`) и агрегатором
(`/zapis`, таблицы `psy_*`). Живёт в `/soprovod`, все таблицы — `sop_*`.
Системы не пересекаются; единственная связь — импорт ЧИТАЕТ `shk_clients`
(и ничего туда не пишет).

Устройство и вход повторяют школьную запись к психологу (/shkola),
гамма своя — слива на лавандовой бумаге, чтобы системы не путались
с первого взгляда.

## Что это

Менеджеры онбординга созваниваются с новыми клиентками школы и вводят их
в профессию. Система хранит список клиенток, расписание менеджеров,
записи на созвоны, отчёты по каждому созвону (анамнез) и статус
онбординга каждой клиентки.

## Роли и вход — как в школе

Единый вход на главной: почта и пароль, «У меня есть аккаунт / Я здесь
впервые». Роль выбирается при регистрации:

- **Клиентка** — доступ открывается сразу: по почте/телефону/телеграму
  подклеивается к списку из школы (или заводится новая карточка). В
  кабинете: ближайший созвон, история, выбор времени (менеджера подбирает
  система — свободного и с наименьшей загрузкой), перенос и отмена по коду
  записи; перенос не освобождает старое место, пока не выбрано новое.
  Личная ссылка из письма (`?k=`) открывает кабинет без пароля.
- **Менеджер** — регистрируется сам, работает после подтверждения
  владельцем. Кабинет: созвоны, расписание, клиентки (карточка с
  анамнезом), профиль.
- **Владелец** — первый зарегистрированный аккаунт; может назначать
  других владельцев. Плюс: менеджеры (подтверждение), статистика,
  настройки, импорт, Telegram.

## Как устроено

- `lib.php` — ядро: база, таблицы, запись, напоминания, Telegram-очередь.
- `api.php` — все действия, диспетчер по `?action=`.
- `cron.php` — планировщик (панель хостинга: `php ~/public_html/soprovod/cron.php`).
- `index.html` + `app.js` + `app.css` — ванильный SPA, одна страница на всех.
- `relay/onboarding_relay.py` (корень репозитория) — реле Telegram, ставится `relay/install-relay-launchd.sh`).

## Скрипты (в папке выше, `relay/`, `deploy/`)

- `deploy/deploy-rsync.sh` — выложить код на хостинг (rsync, только папка `/soprovod`).
- `deploy/backup-to-local.sh` — резервная копия таблиц `sop_*` и кода к себе.
- `relay/install-relay-launchd.sh` — поставить реле Telegram в автозапуск Мака
  (метка `com.soprovod.rele`, журнал `rele.log`).

## Порядок первого запуска

1. `deploy/deploy-rsync.sh` — код уезжает на сервер, таблицы создадутся сами.
2. Открыть https://booking.example.com/soprovod/ и зарегистрироваться —
   первый аккаунт становится владельцем.
3. Настройки → «Обновить список сейчас» — приедут клиентки из школы.
4. Менеджеры регистрируются сами; владелец подтверждает их во вкладке
   «Менеджеры».
5. Telegram: создать бота у BotFather, вписать токен, `relay/install-relay-launchd.sh`.
6. Панель хостинга → Cron: `php ~/public_html/soprovod/cron.php`
   каждые 5–10 минут (пока крона нет, планировщик едет попутно с запросами).

## Правила

- Боевые данные не трогаем; тесты — только на синтетике с уборкой.
- Перед работами и после — `deploy/backup-to-local.sh`.
- Чужие папки и таблицы (`psy_*`, `shk_*`) не трогаем никогда.
